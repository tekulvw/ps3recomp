# NV0039 guest-memory relocation copies

This change addresses a proven dropped command sequence, with menu causality still requiring a controlled native replay. MAG retail's original helper `00E4C960 -> 00982764 -> 009827D0` emits a two-word DMA packet `00082184`, an eight-word copy packet `0020230C`, and an output-offset reset `00042310`. Existing native logs record that sequence on subchannel 1 and explicitly report it unhandled. The resource allocator/compactor `000FF478` emits these copies and then calls `000F9794` (`ResourceBlock::RelocateBulkData`, matched against prototype instructions) to move the resource pointers. This can leave relocated pointers reading the old contents of their new addresses.

## Scope and routing

Intercept only the complete observed default-slot producer form, before either renderer feed or NV4097 state processing: incrementing subchannel-1 DMA methods `0184/0188` (count 2) immediately followed by incrementing `030C..0328` (count 8). The original helper and [RPCS3's register definitions](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/RSX/gcm_enums.h#L711-L722) identify these NV0039 methods. Subsequent count-8 packets are accepted only at the exact next FIFO cursor of this confirmed sequence; a contiguous output-offset reset to zero ends it. A branch, unrelated method, or explicit SET_OBJECT ends the inferred sequence. Incomplete publication parks at the original header, preserves it across repeated drains, and bypasses legacy stuck/recycle heuristics until more words are published.

This is an empirical producer-pattern classifier, not a general model of hardware object binding. The original bootstrap's NV0039 handle has not been established. Any explicit SET_OBJECT on slot 1 disables inference for the session; arbitrary handles are not class IDs. Ordinary slot-1 alpha/blend, eight-register 3D state groups, and shader writes before any SET_OBJECT keep their existing route. No class is inferred from handle low bits, and no other slot is reassigned. Common fences keep their existing handling. Structurally recognized copies with unsupported DMA/format/notify are consumed as failed copies rather than falling through into 3D registers.

## Supported operation and failure behavior

Support byte-column input/output format `0101`, write-only BUFFER_NOTIFY argument 0, DMA `FEED0000` (local) and `FEED0001` (IO-mapped main), offsets, signed row pitches, line length/count. Zero-sized copies are no-ops. The [Linux nouveau copy producer](https://code.googlesource.com/linux/torvalds/linux/+/fdd041028f2294228e10610b4fca6a1a83ac683d/drivers/gpu/drm/nouveau/nouveau_bo0039.c) emits the same contiguous register group and byte strides. [RPCS3's behavioral reference](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/RSX/NV47/HW/nv0039.cpp#L67-L99) establishes signed pitches and stride interpretation; no implementation is copied from it.

Resolve every row using 64-bit arithmetic before writing anything. Local rows must fit configured local memory and the 32-bit address space. Main rows require every IO page to be mapped to a valid 12-bit EA page and each resulting piece to fit configured guest RAM. EA page zero is valid. Rows may span non-contiguous EA pages; a valid first page does not validate a later page. Snapshot all source rows before any destination write, bounded to 64 MiB, so overlapping rows and both move directions preserve source bytes. Use the existing guest block-store helper for reservation notification and mark every destination piece dirty for same-frame texture-content hashing. Modern native PPU load-reserve tokens arm the same 128-byte epoch bitmap as SPU reservations; block notifications invalidate those tokens even for identical replacement bytes or stores to another word in the line. The old generated PPU value-CAS ABI and legacy Windows registry invalidation remain unverified limitations; this patch does not refactor them.

Flush preceding backend work before the CPU copy. Copy execution is synchronous inside the FIFO drain and therefore precedes a following reference publication. Unsupported strides/notify modes, unknown DMA, malformed range, missing IO page, excessive snapshot size, or allocation failure leave the entire destination untouched and report one of at most 16 diagnostics. In checked-reference mode a failed operation latches failure so the runtime cannot advertise completion of an unexecuted copy.

The caller precondition is that the source bytes are CPU-owned and current in guest memory, as with the captured compressed asset payload. This subset copies CPU-backed guest resources; it does not query or reject a GPU-owned source surface. It does not add GPU render-target readback or typeless surface copies; backend flush alone does not make GPU-only pixels appear in guest memory. Such copies remain a separate limitation, and successful menu rendering must be verified on the actual captured asset relocation path.

## Verification plan

The production FIFO regression must fail before implementation on the exact observed default-slot packet. It then verifies bytes, copy-before-reference ordering, no alpha/blend register contamination, unchanged slot-1 shader routing and explicit rebind behavior, local/main DMA, pitched and signed rows, overlap in both directions, IO-page boundaries, and atomic failure. Related checked-reference and guest-report fixtures must remain green. No live game runs or SDK integration are performed from this branch.

## Bounded replay receipts

`PS3RECOMP_NV0039_TRACE_LIMIT` enables successful-copy receipts, defaults to zero, and clamps to 256. Each line includes execution sequence, FIFO IO cursor, source/destination DMA and offset, signed pitches, line length/count, `copied` outcome, and a content hash. Failed operations emit at most 16 reason/cursor diagnostics and latch checked-reference failure. No asset bytes are dumped automatically.

## Focused verification

Run `python3 tools/test_gcm_memory_to_memory.py`. The fixture includes the real production FIFO parser and links the real PPU loader and SPU coherence implementation. Its original retail packet fails on the unmodified base because the following checked fence observes unchanged destination bytes. Cases cover ordinary 3D slot-1 state before binding, explicit rebind, signed pitches, overlap, original 4 MiB continuation, non-contiguous source/destination IO pages, invalid EA page and RAM end, page-zero mapping, unsupported format/notify/DMA and budget, no-op sizes, and 12 partial-publication drains followed by completed copy and fence. Actual PPU word/doubleword LL/SC and SPU LR assertions cover same-value stores, another word in the line, both affected granules, and an unrelated line.

The reference Killzone G6 description reports the same dropped-copy/state-contamination issue and additionally covers GPU surface writeback and cache invalidation. This patch does not claim that broader behavior or a unique diagnosis.
