# Outgoing DMA publication observer

This diagnostic snapshots the source of validated outgoing direct/list PUTs immediately before the normal copy. It never modifies the local store, guest memory, DMA command, tag status or transfer ordering. A PUT record proves the bytes submitted to that copy, not subsequent GPU consumption or a successful atomic commit. PUTLLC/PUTLLUC are outside this hook.

Set `SPU_DMA_PUBLICATION=<hexEAlo>-<hexEAhi>` to snapshot complete, naturally aligned BE32 words in the intersection of an outgoing transfer and that half-open guest range. Partial boundary words are excluded.

To find a pointer before a descriptor buffer is reused, set both `SPU_DMA_PUBLICATION_MATCH_RANGE=<hexEAlo>-<hexEAhi>` and `SPU_DMA_PUBLICATION_MATCH_WORD=<hexBE32value>`. Only complete aligned words in that transfer's intersection are searched. Each transfer scans at most 16 KiB. The first match per transfer logs its guest address and up to 16 surrounding source words, clipped to the configured range and transfer. The match is always included in that window. Zero is a valid search value.

`SPU_DMA_PUBLICATION_INCOMING=1` additionally observes GET and list GET, immediately after the existing copy into LS. Incoming observation is off by default; `0` explicitly keeps it off. A GET record proves the copied bytes at that boundary, not execution of a later job. The observer reads only the copied LS bytes, never rereads guest memory.

`SPU_DMA_PUBLICATION_HEADER_WORDS` chooses 0–8 leading transfer words on a matching record (default 0, off). These words start at transfer LSA, independently of the match-window clipping, and are bounded by the transfer size. They help identify a fetched or published descriptor header. The surrounding match snapshot still has at most 16 words; the combined record has at most 24 words. Header sampling does not occur on a span-only record. The header is a separate diagnostic sample, not an atomic snapshot with the matching words.

`SPU_DMA_PUBLICATION_WORDS` chooses 1–16 words per record (default 16). `SPU_DMA_PUBLICATION_LIMIT` chooses 1–32768 records (default 128). Both modes share one process-global atomic cap, including calls from different generated translation units and concurrent SPU workers. Configuration initializes once using the platform's synchronized once primitive. Malformed or incomplete configuration disables both modes. With no configured mode, there are no additional local-store reads. Once the cap is exhausted, the diagnostic stops scanning. No guest addresses are selected by default.

Records include image ID, physical SPU ID, current PC, command, transfer LSA/EA/size, sample EA, transfer-relative sample/match offsets, word count, truncation and match EA. Direction distinguishes `put` from `get`. Header and payload are comma-separated raw big-endian words. `kind=span` samples the watched intersection; `kind=match` samples a matching descriptor word. PUT data is a pre-copy source snapshot and GET data is a post-copy LS snapshot; enabling logging changes host timing. The record cap bounds output, while the per-transfer bound limits work even when a selected descriptor range contains no matches.

Run `python3 tools/test_spu_dma_publication.py` for manufactured direct/list PUT and GET data, unchanged DMA bytes, optional fetched header sampling, range clipping, exact descriptor matches, trailing 16 KiB matches, strict option validation, unreadable-LS disabled mode, concurrent cap and C++ to C linkage. This fixture does not require game data.
