# PAMF reader metadata

PAMF `0040`/`0041` stores header and multiplexed-data lengths in 2048-byte units. Its stream table is nested under the sequence, grouping period and group; each stream descriptor is 48 bytes. The former implementation interpreted unrelated reserved bytes as offsets and counts, kept eight readers in a host-only registry, and wrote codec fields in host byte order. A real `0041` movie consequently reported zero streams.

This implementation writes the actual 128-byte guest reader and borrows a guest-resident header. `cellPamfReaderInitialize(readerEA, headerEA, u64 fileSize, attribute)` does not allocate, read files, decode or issue playback callbacks. The caller must retain header storage while readers refer to it. A 128-byte reader copy remains usable at another guest address without registering host state. Header-only residency is sufficient: full media size is checked arithmetically, never treated as resident payload size.

The supported format has one grouping period and one group. The parser checks the magic/version, nonzero header size, optional full-file-size equality, nested extents, stream count consistency, known stream types and EP extents before writing the output reader. Unsupported multiple groups/periods return `NOT_AVAILABLE`. Unknown magic and unsupported versions use their distinct PAMF errors. Guest bounds and structural validation apply even without `VERIFY_ON`; this is a conservative HLE policy, not a claim to reproduce every firmware validation quirk. `MINIMUM_HEADER` requires resident structural metadata rather than all header padding. The VM check establishes a valid linear guest-memory range, not per-allocation ownership. Failed initialization leaves the caller's previous reader bytes intact, and overlapping reader/header storage is rejected.

Reader fields use big-endian guest values: header/data sizes at `+0/+8`, attributes at `+0x10`, version at `+0x16`, current stream index at `+0x20`, and header/sequence/period/group/stream pointers at `+0x24/+0x28/+0x2c/+0x30/+0x34`. No host pointer is stored. Reads revalidate the backing header and pointer/index relationship.

Supported queries include stream counts (including VIDEO=20 and AUDIO=21 groups), absolute index selection, actual SDK `cellPamfReaderSetStreamWithTypeAndIndex` (NID `28B4E2C1`, returning the selected absolute index), current index, timestamps, mux-rate code, EP count, elementary-stream filter IDs and AVC/M2V/ATRAC3+/LPCM/AC3 metadata. Multi-byte output is guest-endian. Audio frequency and LPCM bit length are SDK enum values, not literal Hertz/bits. The old non-SDK `SetStreamWithType` helper retains its zero-on-success return for source compatibility. The old speculative EP API and channel selector now report `NOT_AVAILABLE`, rather than fabricating metadata or silently treating a channel as an ordinal. Full EP navigation, PSMF and decoding remain unsupported.

## Evidence

Primary format and ABI reference: [RPCS3 cellPamf.h](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/Cell/Modules/cellPamf.h) and [cellPamf.cpp](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/Cell/Modules/cellPamf.cpp), consulted 2026-10-11. These establish the public reader layout, format offsets, enum representations, error numbers and stream-selection return. They are not proof of complete firmware behavior; the channel-selection implementation explicitly documents firmware quirks, so this patch leaves that operation unsupported.

An operator-supplied retail THX PAMF was independently checked without committing any game bytes: full-file SHA-256 `13370643299e6c4f055e83796aad6f629eb23cdffc9fd18bbef98948a4c2c174`, size 2,732,032 bytes; header 2,048 bytes, data 2,729,984 bytes. Its two descriptors are M2V video (1280×720) and stereo ATRAC3+ (frequency enum 1, meaning 48 kHz). Start/end timestamps are 89,310 and 627,537 in 90 kHz units. Retail's corresponding query path uses counts for categories 20/21 and the formerly missing NID `28B4E2C1`.

## Validation

Run `python3 tools/test_pamf_reader.py` using Python 3.10 or newer. The fixture compiles actual production code, generates the HLE NID table and calls through the actual PPU bridge. It uses independently constructed synthetic headers, copied readers, output canaries, malformed lengths/types, 64-bit size arguments, boundary addresses, M2V/AVC/audio field checks and the real stream-selection NID. Pass a local THX PAMF path as the optional argument to run the same assertions against its first 2048 bytes; no game file is copied into the repository.

The baseline failed the initial guest-reader assertion and printed zero streams. A second test first failed the missing retail NID registration before its export was added. Final focused results: 98 synthetic checks and 100 checks with the real THX header. All existing `tools/test_*.py` scripts are also run before commit; their detailed result belongs in the handoff, not an unverified success statement here.
