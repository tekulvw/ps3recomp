# Output range provenance diagnostics

Set `PS3_OUTPUT_PROVENANCE=<lo>-<hi>` to a hexadecimal half-open guest EA range. Unset, malformed, empty, reversed, or out-of-32-bit-space ranges disable this diagnostic. Environment settings are read once in each emitting translation unit and must be supplied before process startup.

The opt-in diagnostic produces three kinds of `[output-provenance]` records:

* Inline mapper syscalls 330/337 report successful returned ranges overlapping the selected range, their requested arguments, out-param address, LR, and thread id. `size` is the actual rounded reservation or mapped span; `requested_size` is the raw 330 size argument (zero for 337, which has no size argument). `align_or_id` is raw 330 alignment or337 memory id. `request` is the requested 337 starting EA (zero for 330, which has no starting-EA argument). Return values and allocation cursors keep their existing behavior.
* Set `PS3_OUTPUT_PROVENANCE_TARGET=<hex code address>` to enable argument records at that indirect PPU entry. The probe interprets r6 as output EA and r8 as output length for its overlap filter; records include r3..r10, caller LR, thread id, and raw r31. Verify the selected function's ABI before using the filter. It performs no guest pointer dereferences. Direct lifted calls have no entry hook and are outside this diagnostic's scope.
* SPU PUT records appear after the actual host copy and include PC, image id, SPU id, r0, LS address, EA, byte count, and raw r82/r88/r89. Rejected DMA requests produce no copied record. The receipt proves a copy executed; it does not establish allocation ownership or preserve the copied payload.

Each kind has an atomic saturating 64-record budget per emitting translation unit, shared by its threads. Different translation units can emit their own budgets. No guest registers, memory payloads, mapping rules, allocator policy, or DMA completion semantics are modified. The range and argument arithmetic rejects overflow for the diagnostic only.

For a queue producer with a direct callee, choose the last indirectly dispatched wrapper that forwards r6/r8 unchanged, and correlate its arguments with the SPU copy receipt and mapper range records. A valid allocator receipt covering the output supports an ownership collision; an output outside all observed allocated ranges requires tracing its descriptor producer. The absence of a receipt is not proof that no allocation occurred: other allocation APIs, exhausted budgets, and allocations before diagnostic startup remain outside the observation.

`tools/test_output_provenance.py` compiles the actual inline mapper cases and indirect entry prefix, and drives the real SPU DMA implementation against synthetic memory. It verifies disabled/invalid configurations, target and range filtering, zero/oversized spans, bounded concurrent output, mapper return compatibility, and unchanged successful/rejected DMA behavior. Its standalone compiler harness runs on Linux/macOS and explicitly skips Windows. Runtime diagnostics use the existing cross-platform Win32 compatibility primitives; native Windows and Linux execution were not verified during this change.
