# Checked FIFO producer parks

The checked FIFO walker recognizes a mapped JUMP to its current GET cursor as a producer park: it retains GET and re-reads the command on the next drain. Before this correction, the tail stuck-GET watchdog counted that deliberate wait as an unexplained stall. On the ninth unchanged drain it latched `stuck-get`, permanently disabling checked reference completion even when the producer subsequently patched the park.

The focused correction marks a recognized checked self-JUMP as a per-drain producer wait. The existing producer-wait handling resets the stuck counter; the flag also continues to cover incomplete NV0039 publication. The flag is recomputed on every drain, so a patched command receives ordinary validation. Legacy unchecked recovery, checked reference submission/completion, unmapped-branch rejection, malformed-packet handling and budget-based circling detection retain their behavior.

`python3 tools/test_gcm_checked_reference.py` exercises the real production FIFO parser with a controlled backend boundary. Three positive cases park for twelve drains, assert unchanged GET/reference with no draw or fence submission, then patch to a draw plus fence, a branch to the next segment, or a wrapped-ring branch. The draw must reach the backend before checked completion; the exact fence receipt is then published. A fourth case changes the park to an invalid target and must fail. A genuine two-address cycle and an unmapped JUMP continue to latch failure without publishing a fence. Existing held-completion, repeated/wrapped reference, malformed, incomplete, backend-failure, skipped-command and queue-overflow cases remain covered.

On unchanged SDK `c331dcd4b25c93472de55750c56effb91e3e005c`, the extended park regression fails with `stuck-get` before producer patching. It passes with this correction. This proves an SDK control-flow bug; it does not prove the native MAG failure at IO `001BFCD0` took this path because that run did not record the command word. A matching self-JUMP would be `201BFCD0`. The parent-owned diagnostic replay can verify GET, PUT and that word with `GCM_RECDBG` / the existing FIFO trace. No game control or integration is performed from this branch.
